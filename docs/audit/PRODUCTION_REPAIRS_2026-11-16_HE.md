## ההרשמה

שורש הכשל: גרסת PostgREST המותקנת מחזירה `None` כאשר `maybe_single()` לא מוצא אימייל. קריאת `.data` ממנו גרמה ל־500 לפני יצירת משתמש חדש. החיפוש תוקן ונוספה שכבת תאימות לכל הקריאות האופציונליות מסוג זה בבקאנד.

נוספו בדיקות דרך האפליקציה המורכבת להרשמה עם אימייל חדש, אימות קוד וכניסה; בדיקה מול התנהגות ה־SDK המותקן; חזרה לאימות אחרי רענון; ותאימות להתקנות Supabase שיוצרות פרופיל באמצעות Auth trigger. שדות הטופס נקראים במפורש לפי ID, והנתיבים הישנים של הרשמה משתמשים באותו מסלול קוד אימות.

## לפני הפעלה בשרת

1. לגבות את המסד ולהחיל את כל המיגרציות לפי סדר באמצעות `backend.services.migration_runner.apply_migrations`. התיקון החדש נמצא ב־`database/migrations/20261117_production_repairs.sql`; יש להחיל גם את מיגרציות המנויים שהתווספו ב־16.11. אין לערוך קבצים שכבר נרשמו עם checksum.
2. לקבוע `SUBSCRIPTION_PROVIDER=stripe`, כפי שמוגדר כעת ב־`render.yaml`. לקבוע `STRIPE_SECRET_KEY` ו־`STRIPE_WEBHOOK_SECRET` מתאימים לסביבת test/live. מזהי מחירי PRO/PREMIUM, אם הוגדרו, חייבים להתאים למחיר החודשי שבקטלוג השרת.
3. להגדיר `STRIPE_CONNECT_CLIENT_ID` ו־`STRIPE_CONNECT_WEBHOOK_SECRET`. בפורטל Stripe יש לאפשר Connect OAuth ולרשום את כתובת החזרה המדויקת: `BASE_URL/api/v1/merchant-payments/callback`.
4. הודעות מנויים נשלחות ל־`/api/v1/webhooks/stripe`; הודעות מחשבונות העסקים ל־`/api/v1/webhooks/stripe/connect`. נדרשים אירועי checkout completed/async succeeded/async failed/expired ו־charge refunded בחיבור העסקים. חיבור מנויים משתמש בהגדרות האירועים שלו.
5. לכל עסק: הגדרות → רכישה ומשלוחים → הגדרת עלויות וחיבור חשבון Stripe של העסק. אין להזין מפתחות סודיים של העסק בדפדפן. חיבור החשבון נעשה באתר Stripe.
6. לוודא `RESEND_API_KEY`, כתובת שולח מאומתת, כתובות Supabase וקישורי OAuth. להריץ בדיקת staging של הרשמה ומייל אמיתי, חיבור עסק, רכישה ב־Stripe test mode, תשלום, החזר, תפוגה וביטול מנוי. רק בדיקה זו מאמתת שהחשבונות וה־webhooks החיצוניים הוגדרו בפועל.

התאמה למדינות ויכולות חשבון נקבעת על ידי Stripe בחשבון המחובר. אם עסק אינו זכאי לחשבון Stripe, נדרש ספק נוסף עם API מאומת; הקוד אינו מעביר כספים למסוף אחר או לחשבון הפלטפורמה במקום זאת.

המימוש משתמש ב־[Direct charges של Stripe](https://docs.stripe.com/connect/direct-charges.md?platform=web&ui=stripe-hosted) וב־[Connect OAuth](https://docs.stripe.com/connect/oauth-reference). הגדרת credentials, Connect והרשאות בספק עצמו אינה ניתנת לאימות בבדיקות המקומיות.
