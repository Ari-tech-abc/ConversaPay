- בדיקת שיוך לקוח ושיחה לאותו עסק לפני יצירת הזמנה, ובנוסף טריגר PostgreSQL לכתיבה דרך service_role.
- הסרת פרטי שגיאות פנימיים מתשובת /ready.
- כיבוי /openapi.json בפרודקשן, בנוסף לדפי התיעוד.
- הסרת שמירת ושחזור HTML של הזמנות ממטמון הדשבורד ומחיקת מטמון v2 הישן; שמירת ערכים וטקסט בלבד.
- חסימת javascript ו־data בקישורי מוצר ובתמונות בעת יצירה ועדכון; קבלת HTTP/HTTPS ללא פרטי הזדהות בלבד.
- שמירת מזהה עסק הדמו conversapay כמזהה מערכת.
- דרישת אימות מייל לפני פטור בעלים ממפתח ווידגט.
- תיקון פענוח טוקני הזמנות עם חתימה בינארית המכילה נקודה; בדיקות לפקיעה ולהחלפת מזהה הזמנה.
- הסרת python-jose ו־ecdsa שאינן בשימוש מהתלויות ומהסביבה המקומית.

## האתר הפעיל והפריסה

הדף הראשי החזיר 200, /docs החזיר 404 ו־/openapi.json החזיר 200 עם סכמת API. נמצאו כותרות CSP, HSTS, nosniff ו־Referrer-Policy.

/ready החזיר 503 והודעתו אישרה ש־DATABASE_URL אינו מוגדר בשרת. יש להגדיר את החיבור בסביבת האירוח עם ערך מאושר; לא הומצא ולא הוחלף connection string.

כדי להפעיל את התיקונים יש לפרוס את הקוד והתלויות המעודכנות ולהחיל database/migrations/20261004_security_order_tenants.sql באמצעות מנגנון המיגרציות הקיים. הטריגר מגן על כתיבות חדשות ועדכונים; אינו מתקן קשרים שגויים קיימים. לא נבדקו נתוני פרודקשן פרטיים ולא בוצעה פריסה.

CSP עדיין מאפשר unsafe-inline בשל סקריפטים ומטפלי אירועים מוטמעים בממשק. הידוקו דורש מעבר לקבצים חיצוניים או ל־nonce ובדיקת התאימות להתחברות Google ולווידגט. Redis אינו מוגדר באתר שנבדק, ולכן הגבלת בקשות בין תהליכים אינה מאומתת. הגבלת הדמו לפי IP עשויה לשתף מכסה בין משתמשים באותה רשת.

הגדרות Supabase/Render הפעילות, הרשאות ניהול, סודות בשרת ותשלומים אמיתיים לא אומתו. זו בדיקת קוד ותקינות ממוקדת, ולא אישור שאין חולשות נוספות.
