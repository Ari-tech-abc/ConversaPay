מדריך הטמעה

כך מטמיעים את הווידג׳ט באמת

המדריך הזה תואם לזרימה שהמערכת מפעילה כיום: וידג׳ט חיצוני משתמש ב-Business UUID וב-Widget API Key, והשרת מאמת את המפתח לפני טעינת ההגדרה ושליחת הודעות.

לפני שמתחילים

מה צריך?

1עסק פעילצריך Business UUID אמיתי של העסק. זהו מזהה ה-UUID של הרשומה ב-businesses, לא שם העסק ולא slug כמו business_....
2מסלול PRO או PREMIUMגישה לווידג׳ט חיצוני של עסק אמיתי חסומה במסלול FREE.
3Widget API Keyהמפתח נשלח בכל בקשה לווידג׳ט בכותרת X-Widget-Key. הוא מוצג רק בזמן היצירה שלו.
חשוב: מה לא היה נכון במדריך הישן
המערכת אינה מאמתת את הווידג׳ט לפי Origin/Referer, אין במסלול הנוכחי של הדאשבורד מסך ניהול מפתחות ייעודי, ואין צורך להוסיף API Secret לקוד האתר. לכן המדריך החדש לא מציג שלבים שלא קיימים בפועל.
בחירת דרך

איך מטמיעים?

שלב 1 — יוצרים שלד HTML

הווידג׳ט לא דורש div מיוחד. הסקריפט מייצר בעצמו את הממשק ומוסיף אותו ל-body.

<!doctype html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width,initial-scale=1">
  <title>My website</title>
</head>
<body>
  <main>
    <h1>My website</h1>
  </main>

  <!-- ConversaPay widget goes here -->
</body>
</html>

שלב 2 — מוסיפים את הסקריפט האמיתי

את הסקריפט אפשר לשים לפני </body>. משתמשים בכתובת ה-widget.js שהמערכת עצמה מפרסמת.

<script
  src="https://www.conversapay.org/frontend/js/widget.js"
  data-business-id="YOUR_BUSINESS_UUID"
  data-api-key="YOUR_WIDGET_API_KEY"
  data-position="bottom-right"
  data-color="#635bff"
  defer></script>
מה הקוד עושה?
widget.js קורא את data-business-id ואת data-api-key, טוען את /api/v1/widget/config/{business_id}, שולח את המפתח בכותרת X-Widget-Key, ולאחר מכן שולח הודעות ל-/api/v1/chat עם אותו מפתח.

שלב 3 — בודקים את הקוד

העמוד נטען ב-HTTPSמומלץ להריץ אתר אמיתי ב-HTTPS.
הווידג׳ט מופיעאם הוא לא מופיע, בדקו קודם Business UUID ו-Widget API Key.
שליחת הודעה עובדתפתחו את הצ׳אט ושלחו הודעה. כשל 401/403 מצביע בדרך כלל על הרשאת הווידג׳ט או מפתח לא תקין.
הקוד נטען פעם אחתאל תכניסו את אותו widget.js פעמיים לאותו עמוד.

שלב 1 — מתקינים את התוסף

המערכת כוללת את wordpress-plugin/conversapay-chat.php. מתקינים אותו כתוסף WordPress ומפעילים אותו.

1Plugins → Add New → Upload Pluginהעלו את קובץ התוסף ZIP אם יש לכם חבילת ZIP.
2מפעיליםהפעילו את Talk2Pay Chat.
3פותחים Settings → Talk2Pay Chatשם התוסף מנהל את Business ID, כתובת השרת, API Key, מיקום וצבע.

שלב 2 — מגדירים את הווידג׳ט

הדביקו Business UUID ו-Widget API Key, השאירו את כתובת השרת על https://www.conversapay.org אם זו כתובת המערכת שלכם, ובחרו מיקום וצבע.

איך התוסף מטמיע?
התוסף מוסיף ל-wp_footer סקריפט widget.js עם data-business-id, data-api-key, data-position ו-data-color. אפשר גם להשתמש ב-shortcode [conversapay_chat].

שלב 3 — שליטה במיקום

כל העמודיםברירת המחדל של התוסף.
דף הביתהתוסף בודק is_front_page().
עמודים נבחריםהתוסף משתמש ברשימת מזהי עמודים שבחרתם.
[conversapay_chat]
אבחון

אם הווידג׳ט לא עובד

הווידג׳ט לא מופיע בכללפתחו DevTools → Network וחפשו בקשה ל-/api/v1/widget/config/{business_id}. בדקו שה-Business UUID תקין ושהמפתח נשלח.
קיבלתם 401השרת מצפה ל-Widget API Key תקין בכותרת X-Widget-Key. במסלול PRO/PREMIUM מפתח לא תקין חוסם את הגישה.
קיבלתם 403בדקו שהעסק אינו במסלול FREE. הווידג׳ט החיצוני של עסק אמיתי דורש PRO או PREMIUM.
הווידג׳ט מופיע אבל אין תשובהבדקו בקשת POST ל-/api/v1/chat, את סטטוס התגובה ואת Network Console. אין צורך להוסיף API Secret לדפדפן.

הערה על יצירת API Key

בגרסה הנוכחית קיימים ב-API endpoints ליצירה, רשימה וביטול של Widget API Keys, אבל אין בדאשבורד מסך UI ייעודי לניהול שלהם. לכן אל תחפש במדריך כפתור שאינו קיים.
