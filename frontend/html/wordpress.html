התקנת התוסף ConversaPay AI Chat Assistant

חמש דקות, בלי לגעת בקובץ קוד אחד באתר.

1
ארזו את התוסף

קחו את התיקייה wordpress-plugin מהריפו של ConversaPay וארזו אותה לקובץ ZIP בשם conversapay-chat.zip.

2
העלו והפעילו ב-WordPress

בממשק הניהול: Plugins → Add New → Upload Plugin, העלו את ה-ZIP ולחצו Activate.

3
פתחו את מסך ההגדרות

התוסף מוסיף עמוד תחת Settings → ConversaPay Chat, בכתובת /wp-admin/options-general.php?page=conversapay-chat.

4
מלאו את שלושת השדות החיוניים

Business ID, כתובת ConversaPay ו-Widget API Key. אחר כך בחרו מיקום, צבע והיכן להציג את הווידג׳ט.

5
שמרו והפעילו

לחצו שמור והפעיל. הכרטיס בצד ימין יעבור למצב "מוכן לטעינה באתר" ברגע שיש Business ID תקין.

הטמעה נקודתית עם Shortcode

רוצים את הווידג׳ט רק בתוך עמוד או פוסט מסוים? הוסיפו את ה-shortcode בעורך. הוא עוקף את כללי "הצגה באתר".

Shortcode 
[conversapay_chat]
PHP · תבנית או בלוק Gutenberg 
<?php echo do_shortcode( '[conversapay_chat]' ); ?>

בלי תוסף: קטע קוד ל-functions.php

אם אתם מעדיפים לא להתקין תוסף, הוסיפו את הקוד הבא ל-functions.php של תבנית הבת (child theme). הוא מזריק את אותו סקריפט בדיוק ל-footer.

PHP · child-theme/functions.php 
/**
 * ConversaPay chat widget.
 * Paste at the end of your child theme functions.php file.
 */
add_action( 'wp_footer', function () {
    if ( is_admin() ) {
        return;
    }

    $conversapay_url = 'https://www.conversapay.org';
    $business_id     = 'YOUR_BUSINESS_UUID';
    $widget_api_key  = 'YOUR_WIDGET_API_KEY';

    printf(
        '<script src="%s/frontend/js/widget.js" data-business-id="%s" data-api-key="%s" data-position="bottom-right" data-color="#635bff" defer></script>',
        esc_url( untrailingslashit( $conversapay_url ) ),
        esc_attr( $business_id ),
        esc_attr( $widget_api_key )
    );
}, 99 );
אל תערכו את functions.php של תבנית האם. עדכון תבנית ימחק את השינוי והווידג׳ט ייעלם מהאתר.

שליטה מהקוד שלכם

אחרי שהווידג׳ט נטען הוא חושף API קטן על window. שימושי לכפתור "דברו איתנו" משלכם.

// Open the chat window from any element on the page.
document.getElementById('talk-to-us').addEventListener('click', function () {
  window.ConversaPayWidget?.open();
});

// Close it again.
window.ConversaPayWidget?.close();

אפליקציות SPA (React, Vue, Next.js)

הווידג׳ט מזריק את עצמו פעם אחת ומוגן מפני כפילויות. טענו אותו ברמת ה-layout או ה-index.html, לא בתוך קומפוננטה שנטענת מחדש בכל ניווט.

JavaScript · הזרקה חד-פעמית 
function loadConversaPay() {
  if (document.querySelector('script[data-conversapay]')) return;

  const script = document.createElement('script');
  script.src = 'https://www.conversapay.org/frontend/js/widget.js';
  script.dataset.businessId = 'YOUR_BUSINESS_UUID';
  script.dataset.apiKey = 'YOUR_WIDGET_API_KEY';
  script.dataset.conversapay = 'true';
  script.defer = true;
  document.body.appendChild(script);
}

loadConversaPay();

הווידג׳ט לא מופיע? התחילו כאן

פתחו את קונסול הדפדפן (F12) בעמוד עם ההטמעה והשוו לתסמינים למטה.

שום דבר לא קורה, ואין אפילו שגיאה בקונסול

הווידג׳ט מפסיק בשקט כאשר ה-Business ID אינו UUID תקין. זו הסיבה הנפוצה ביותר.

ודאו שהערך נראה בדיוק כך, 36 תווים עם מקפים:

3f2b9c14-7d51-4a8e-b0c6-19ee5a77d240

שם עסק, אימייל או מספר מזהה פנימי לא יעבדו. העתיקו את הערך מהדאשבורד.

401 · Valid widget API key required

כל הטמעה בדומיין חיצוני חייבת לשלוח מפתח widget פעיל. בדקו לפי הסדר:

1. המפתח נוצר בדאשבורד ועדיין פעיל, לא בוטל.
2. המפתח שייך לאותו עסק כמו ה-Business ID.
3. data-api-key אכן נמצא בתג הסקריפט ולא נחתך בהעתקה.

בקשות מהדומיין של ConversaPay עצמו ומ-localhost פטורות מהמפתח, ולכן בדיקה מקומית עלולה "לעבוד" בזמן שפרודקשן נכשל.

403 · External widget embeds require PRO or PREMIUM

מסלול FREE מאפשר שיחות רק בתוך ConversaPay. הטמעה באתר חיצוני פתוחה במסלולי PRO ו-PREMIUM בלבד.

מעבר לשדרוג מסלול
403 · Subscription has expired

המסלול עדיין רשום כ-PRO או PREMIUM אך תאריך התפוגה עבר, והווידג׳ט נחסם מיידית בכל האתרים החיצוניים. חדשו את המנוי או בדקו ב-Stripe שהחיוב האחרון עבר.

שגיאת CORS בקונסול

נתיבי הווידג׳ט והצ׳אט פתוחים לכל דומיין, ולכן שגיאת CORS כאן כמעט תמיד מצביעה על כתובת שגויה ולא על הרשאות.

הנתיבים הציבוריים:

/api/v1/widget/* · /api/v1/chat · /api/v1/orders/* · /api/v1/webhooks/*

אם השגיאה מופיעה על נתיב אחר, כמו /api/v1/auth, הוא אינו מיועד להטמעה בדפדפן מדומיין זר. הדומיין שלכם צריך להיות ברשימת ה-CORS של השרת רק אם אתם קוראים ל-API הפרטי.

ודאו גם שאין הפרש http מול https או www מול דומיין חשוף בין הכתובת בסקריפט לכתובת האמיתית.

אימות דומיין והגבלות מסלול

הוסיפו כל דומיין שבו הווידג׳ט רץ ברשימת הדומיינים בדאשבורד. הזינו את הדומיין בלבד, בלי פרוטוקול ובלי סלאש בסוף:

example.com ✔ www.example.com ✔ דומיין נפרד, יש להוסיף בנפרד https://example.com/ ✘ בלי פרוטוקול ובלי סלאש

מספר הדומיינים מוגבל לפי מסלול. אם הגעתם למגבלה, הסירו דומיין ישן לפני שתוסיפו חדש. תת-דומיינים כמו shop.example.com נחשבים כרשומה נפרדת.

ניהול דומיינים
Webhooks: תשלומים ו-WhatsApp

כתובת ה-Webhook של WhatsApp:

https://www.conversapay.org/api/v1/whatsapp/webhook

ה-Verify Token ב-Meta חייב להיות זהה בתו לזה שהוזן במסך ההגדרות. אם האימות עובר אבל אין תשובות, ה-Phone Number ID וה-Access Token כנראה שייכים לשני נכסים שונים ב-Meta.

בתשלומים: אם המסלול נשאר FREE אחרי תשלום מוצלח, ה-webhook של Stripe לא הגיע. בדקו את יומן ה-Webhooks ב-Stripe וודאו שהכתובת מצביעה לדומיין הפרודקשן ולא לכתובת פיתוח.

הגדרות WhatsApp
הכל נראה תקין, אבל האתר מציג גרסה ישנה

תוספי קאש ו-CDN הם החשוד המיידי. נקו את הקאש של האתר, את קאש ה-CDN (למשל Cloudflare) ואת קאש הדפדפן, ואז טענו מחדש עם Ctrl+Shift+R.

אם יש לכם Content Security Policy, הוא חייב להתיר את הדומיין של ConversaPay גם ב-script-src וגם ב-connect-src.
